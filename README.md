# 公众号大事记助手

从**自己的**微信公众号后台抓取已发表图文，按可配置的规则筛出"重大事件"，生成 Excel 台账与大事记事实底稿。

适合需要定期整理年度大事记、年鉴、成果汇编的单位（企业、机构、社会组织），把"翻几百篇历史图文找素材"这件事自动化。

> 只支持抓取**你本人有管理员权限**的公众号，走的是公众号后台自己的接口，不是爬虫。

## 能做什么

```
扫码登录 → 翻后台发表列表 → 逐篇取正文 → 本地规则分类 → 导出 Excel / Markdown
```

- **断点续传**：被频控、按 Ctrl+C、断网都不丢进度，下次从断点接着跑
- **规则可调**：分类全靠 `rules.yaml` 里的词表，改词不用改代码，重算不出网
- **可溯源**：每条候选都带原文链接和命中词，人工复核时能一键回到原文
- **人工改判可固化**：在 Excel 里改类别，导入后写入 `overrides.yaml`，重新导出不丢
- **对账补漏**：拿后台列表和本地库逐条比对，专治"翻页跳条目"导致的静默漏稿

## 快速开始

1. 装依赖（建议 Python 3.10+）

```bash
python -m pip install -r requirements.txt
```

扫码登录会依次尝试**本机 Edge → 本机 Chrome → Playwright 自带内核**，Windows / macOS 一般都自带前两者，不需要额外下载浏览器。

只有两者都不存在时（精简系统、容器、无头服务器）才需要装内核，国内建议走镜像：

```bash
# Windows PowerShell
$env:PLAYWRIGHT_DOWNLOAD_HOST = "https://cdn.npmmirror.com/binaries/playwright"
python -m playwright install chromium
```

2. 准备配置

```bash
cp config.example.yaml config.yaml   # Windows: copy config.example.yaml config.yaml
cp rules.example.yaml rules.yaml
```

改 `config.yaml` 里的两处：

```yaml
account:
  nickname: "你的公众号名称"   # 仅用于日志和自动搜 fakeid
  brand: "示例单位"            # 导出文件名与台账标题用，可填中性词
```

3. 运行

```bash
python run.py menu        # 交互菜单（Windows 可双击 启动.bat）
python run.py list --full # 或直接跑全量
```

第一次会弹出浏览器，用**公众号管理员微信**扫码登录。登录态存 `data/auth.json`，大概能复用几小时，过期后脚本会自己弹窗让你再扫一次。

4. 打开 `out/` 下的台账

## 产出什么

全部在 `out/` 目录（默认被 `.gitignore` 忽略，不会上传）：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| `<brand>大事记台账_<年>.xlsx` | 6 个页签：候选 / 全年稿件汇总 / 待核实 / 年度参考 / 已排除 / 统计 | 事实底稿，可筛选、可溯源 |
| `大事记索引_<年>.md` | 按月份分组的候选清单，每条带摘要与原文链接；文末附全年稿件流水 | 交给 AI 撰写正式大事记 + 核对漏稿 |
| `已排除_<年>.md` | 被排除的全部条目及原因 | 检查有没有误杀 |
| `pilot.md` | 最近 N 篇的逐条判定 | 调规则时看 |

「置信」和「复核状态」是两列，互不干扰：前者是机器的判断（高/中），后者是你的结论（未复核/已确认/已排除）。

## 命令一览

| 命令 | 作用 |
| --- | --- |
| `python run.py menu` | 交互菜单（日常只用这个） |
| `python run.py list --full` | 按 `since` 全量往前翻 |
| `python run.py list --backfill --before 2026-01-01` | 往前补历史 |
| `python run.py body` | 只抓正文（补上次没抓完的） |
| `python run.py classify --replay` | 只重新分类，秒级、不出网 |
| `python run.py export` | 只导出台账 |
| `python run.py verify --since 2026-01-01` | 对账补漏 |
| `python run.py import-xlsx` | 从台账读回人工改判 |
| `python run.py status` | 查看库内状态 |
| `python run.py pilot --n 10` | 试跑最近 10 篇 |

耗时参考：列表每页 20 条、页间隔 8–15 秒，140 篇约 2 分钟；正文一次群发一次请求、间隔 6–12 秒，140 篇约 25–30 分钟。全号 1400+ 篇约 72 页，分 2–3 次跑。

## 分类是怎么判的

```
得分 = Σ 权重(strong 2.5 / normal 1.0) × 字段权重(标题 1.8 / 摘要 0.6 / 正文 0.8)
       + 1.0（标题命中 2 个以上 strong 时）
≥ 5.0    高置信
2.5–5.0  置信中（进待核实）
< 2.5    不入候选
```

**栏目优先**：很多单位习惯把标题写成「正文标题 | 栏目」，脚本会把栏目拆出来单独存。命中 `channels` 里登记的栏目时直接给 6 分底座（超过高置信线），不靠关键词猜——编辑打的标签比词表可靠得多。

```yaml
# rules.example.yaml 里的示例映射，改成你自己公众号的栏目标签
channels:
  荣誉播报: honor
  业绩捷报: case_achievement
  党建工作: party_building
  专业视点: exclude_pro
  讲座预告: exclude_notice
  新闻简讯: null            # 内容太杂，只记录不定性，交给关键词
  年度案例: exclude_annual_case
```

**判定顺序**（`classify.py`）：先事件打分，再排除。事件分够线就归类返回，不会跑到排除逻辑——所以「荣誉播报」栏目里的文章不会被「讲座」这类词误排除。

**只靠正文命中的不算高置信**：正文里几乎每篇都会提到公益、宣讲、社区这类词，所以标题和摘要都没命中、只有正文命中时，最多记为「置信中」，单独标 `仅正文命中`。

排除类是"多组词同时出现才排除"的逻辑，避免误杀：

| 排除类 | 触发条件 |
| --- | --- |
| 节日祝福 | 标题同时含节日词和祝福词，且不含事件词 |
| 常规讲座 | 标题同时含讲课形式词和「应邀/开展/走进」，且不含「本单位/举办/主办」 |
| 个人公益 | 标题含「某人 + 走进/来到某地」，且不含「本单位/志愿团队/携手」 |
| 个人履职 | 标题含履职/人大/政协专栏等，且不含「本单位/当选/受聘」 |
| 专业文章 | 标题含实务/解读/浅析/评审规则等，但含「举办/论坛/揭牌」时不算 |
| 招聘 / 预告通知 / 业务宣传 / 内部工作会 / 年度案例发布 | 见 `rules.example.yaml` |

年度总结类（含"十件大事/回顾/盘点/年度案例"等）一律不排除，并标 `annual_review` 置顶——写大事记时这是最好的交叉校验源。

## 改造自己的规则

只改 `rules.yaml` 里的词，不动代码：

```bash
python run.py classify --replay   # 本地重算，不出网
python run.py pilot --n 10        # 看小样本判定对不对
```

调稳了再跑 `python run.py export` 出台账。分类是本地算的，不消耗请求额度，可以反复调。

## 已知坑（已处理，改代码前先看）

1. **列表接口不能带 fakeid**。抓自己的号传 `fakeid` 会直接返回 `200013 freq control`，去掉就正常。
2. **文章页 `/s` 会被环境验证拦**。`https://mp.weixin.qq.com/s?...` 对本机 IP 常跳 `wappoc_appmsgcaptcha`，连真实浏览器都拦。所以正文改走后台 `cgi-bin/appmsg?action=edit&appmsgid=...`，返回的 `app_msg_info` 里带完整 `content` HTML，同域同会话不会被验证。
3. **每页 20 条有效**。早期误以为上限是 5。
4. **多图文群发**：一次群发多篇时接口只返回首篇，其余在首篇的 `multi_item` 数组里。必须展开 `multi_item` 按 `seq` 映射，否则第 2 篇会拿到第 1 篇的正文。
5. **循环变量不要用 `s`**：`run_body` 里 `s` 是 requests session，被内层 `for s in subs` 遮蔽过一次，导致第 2 篇之后所有请求报 `dict.get() takes no keyword arguments`。
6. **网络异常绝不能记成「已删」**。`body_status=2` 是终态、不会再重试；只有接口明确返回 64501/200009 才是真删除（走 `ArticleGone`），其他异常记 `4`（失败，下次重试）。
7. **列表翻页的步长是「群发数」，不是「条目数」**。`begin` 是第几次群发的序号；一页里如果某次群发含 2 篇，返回条目会比 `count` 多。早期用 `begin += len(items)` 推进，每页多跳 1 个群发 → 静默漏稿。现在统一 `begin += count`，并新增 `verify` 做全量对账。

## 常见错误码

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| ret=200013 | 频控 | 脚本会先长休重试一次，仍失败则停下，断点已存，1 小时后再跑 |
| ret=200002/200003/-6 | 登录态过期 | 重新运行，扫码即可 |
| ret=64501/200009 | 图文已删除或不存在 | 记为「已删」，不影响其他文章 |
| 61004 | IP 不在白名单 | 只有走官方接口才会遇到，本工具不走 |

## 隐私与安全

仓库里**只有代码和示例配置**，以下都已在 `.gitignore` 里排除：

| 路径 | 为什么不能传 |
| --- | --- |
| `data/auth.json` | 等同账号会话凭证，泄露等于把后台交出去 |
| `data/browser_profile/` | 浏览器 cookie 与指纹 |
| `data/wechat.db` | 抓到的全部文章标题、正文、原文链接 |
| `out/` | 导出的台账与索引，同样是真实内容 |
| `config.yaml` | 含公众号名称、fakeid |
| `rules.yaml` | 规则里常写进本单位的品牌词、栏目名、地域 |

自己用的时候这些文件照常留在本地，只是不进版本库。如果你是先提交后补的 `.gitignore`，**已经进入提交历史的文件不会被新规则清掉**，需要 `git rm --cached` 显式移除，必要时用 `git filter-repo` 清洗历史。

## 注意

- `config.yaml` 里的 `page_interval`、`body_interval` **不要调小**。省下的是几分钟，代价是账号被频控甚至停抓；默认策略是"宁可慢也不要被封"
- 首次全量建议 22:00 后跑，避免与人工操作后台撞车
- 跑正文期间别关窗口、别休眠，脚本占用本机网络
- `data/wechat.db` 是唯一数据源，删了要重抓
- 请遵守微信公众平台的服务条款，仅抓取自己有权访问的内容，控制请求频率
